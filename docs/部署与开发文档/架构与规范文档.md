## **1\. 架构决策记录 (Architecture Decision Records \- ADR)**

本节记录项目中的关键技术决策，包括选择的理由和替代方案。

### **1.1 技术栈选型决策**

| 决策 ID | 决策项 | 选择方案 | 替代方案 | 决策理由 |
| :---- | :---- | :---- | :---- | :---- |
| **ADR-001** | 后端语言 | Rust | C++/Go/Node.js | 内存安全、高性能、跨平台支持、丰富的生态系统 |
| **ADR-002** | 桌面应用框架 | Tauri 2.0 | Electron/Flutter Desktop | 更小的二进制文件、更好的性能、原生系统集成、版本稳定性 |
| **ADR-003** | 前端框架 | React + TypeScript | Vue.js/Svelte | 成熟生态、类型安全、丰富的组件库 |
| **ADR-004** | 样式框架 | Tailwind CSS | Styled Components/CSS Modules | 快速开发、一致性设计、小体积 |
| **ADR-005** | 状态管理 | Zustand | Redux/Context API | 轻量级、易于使用、减少样板代码 |
| **ADR-006** | 文件格式 | Fountain | Final Draft XML/自定义格式 | 纯文本、版本控制友好、行业标准 |
| **ADR-007** | PDF 生成 | wkhtmltopdf + HTML | LaTeX/PDFKit | 灵活布局、易于定制、跨平台支持 |
| **ADR-008** | 数据存储 | 临时文件系统 + 本地文件 | SQLite/JSON 文件 | 简单直接、版本控制友好、支持自动保存和恢复 |
| **ADR-009** | 文件管理 | 临时文件 + 用户选择路径 | 直接文件操作 | 支持未保存状态管理、崩溃恢复、跨平台兼容 |

### **1.2 核心架构图**

**系统架构概览：**

```
┌─────────────────────────────────────────────────────────────┐
│                    ScriptWriter 桌面应用                    │
├─────────────────────────────────────────────────────────────┤
│  前端层 (React + TypeScript + Tailwind CSS)                │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐          │
│  │  编辑器组件  │ │  导航面板    │ │  提纲面板    │          │
│  └─────────────┘ └─────────────┘ └─────────────┘          │
├─────────────────────────────────────────────────────────────┤
│  Tauri 通信层 (IPC)                                        │
├─────────────────────────────────────────────────────────────┤
│  后端层 (Rust)                                             │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐          │
│  │ Fountain    │ │ PDF 生成    │ │ 文件管理    │          │
│  │ 解析器      │ │ 引擎        │ │ 服务        │          │
│  └─────────────┘ └─────────────┘ └─────────────┘          │
├─────────────────────────────────────────────────────────────┤
│  数据层 (本地文件系统)                                      │
│  ┌─────────────┐ ┌─────────────┐                          │
│  │ .fountain   │ │ .md         │                          │
│  │ 文件        │ │ 提纲文件    │                          │
│  └─────────────┘ └─────────────┘                          │
└─────────────────────────────────────────────────────────────┘
```

**数据流架构：**

1. **用户输入** → 前端编辑器组件
2. **格式转换** → Tauri IPC → Rust 后端
3. **数据持久化** → 本地文件系统
4. **实时预览** → 前端渲染引擎
5. **PDF 导出** → HTML 模板 → wkhtmltopdf

## **2\. 代码质量与开发规范**

### **2.1 编码规范与风格**

**Rust 后端规范：**
* **语言规范：** 遵循 Rust 官方 clippy 建议和 rustfmt 格式化标准
* **格式化工具：** 强制使用 `rustfmt`，配置规则文件位于：`rustfmt.toml`
* **Linting 规则：** 必须通过 `clippy` 的所有警告级别检查
* **文档注释：** 所有公共 API 必须包含完整的文档注释
* **错误处理：** 使用 `Result<T, E>` 进行错误处理，避免 `unwrap()` 在生产代码中使用

**前端规范：**
* **语言规范：** 遵循 Airbnb TypeScript Style Guide
* **格式化工具：** 强制使用 Prettier，配置规则文件位于：`.prettierrc`
* **Linting 规则：** 必须通过 ESLint 的所有 Error 级别检查
* **类型安全：** 严格使用 TypeScript，禁用 `any` 类型
* **组件规范：** 使用函数式组件和 Hooks，遵循 React 最佳实践

**文件组织规范：**
```
src/
├── backend/           # Rust 后端代码
│   ├── src/
│   │   ├── lib.rs    # 库入口
│   │   ├── fountain/  # Fountain 解析模块
│   │   ├── pdf/      # PDF 生成模块
│   │   └── file/     # 文件管理模块
│   └── Cargo.toml
├── frontend/          # React 前端代码
│   ├── src/
│   │   ├── components/ # React 组件
│   │   ├── hooks/     # 自定义 Hooks
│   │   ├── stores/    # Zustand 状态管理
│   │   └── types/     # TypeScript 类型定义
│   └── package.json
└── docs/             # 项目文档

### **2.2 代码审查 (Code Review) 规范**

* **Pull Request (PR) 要求：** PR 必须关联一个 GitHub Issue；必须通过所有 CI 检查
* **审查标准：** 关注业务逻辑正确性、错误处理、安全性和可读性
* **合并要求：** 必须至少获得 1 个维护者的批准（Approve）
* **自动化检查：** 所有 PR 必须通过以下检查：
  - Rust: `cargo clippy` 和 `cargo test`
  - Frontend: `npm run lint` 和 `npm run test`
  - 构建检查：`npm run build` 和 `cargo build`

### **2.3 Git 工作流规范**

* **分支策略：** 使用 Git Flow 模型
  - `main`: 生产就绪代码
  - `develop`: 开发分支
  - `feature/*`: 功能分支
  - `hotfix/*`: 紧急修复分支
* **提交信息：** 遵循 Conventional Commits 规范
  - `feat:` 新功能
  - `fix:` 错误修复
  - `docs:` 文档更新
  - `style:` 代码格式调整
  - `refactor:` 代码重构
  - `test:` 测试相关
  - `chore:` 构建过程或辅助工具的变动

## **3\. 测试编写规范**

### **3.1 测试分层策略**

| 测试类型 | 覆盖目标 | 负责人 | 建议覆盖率 | 工具 |
| :---- | :---- | :---- | :---- | :---- |
| **单元测试 (Unit Test)** | 单个函数/模块，无外部依赖 | 开发工程师 | >= 80% | Rust: `cargo test`, Frontend: Jest |
| **集成测试 (Integration Test)** | 模块间接口、文件 I/O 交互 | 开发工程师 | >= 60% | Rust: 集成测试, Frontend: React Testing Library |
| **端到端测试 (E2E Test)** | 完整用户操作流程 | 开发工程师 | 关键路径 100% | Playwright |
| **性能测试 (Performance Test)** | 响应时间、内存使用 | 开发工程师 | 核心功能 100% | Rust: criterion, Frontend: Lighthouse |

### **3.2 单元测试编写约定**

**Rust 后端测试：**
* **命名规范：** 测试文件命名为 `[模块名].rs`，测试函数命名为 `test_[功能描述]`
* **测试结构：** 使用 `#[cfg(test)]` 模块组织测试代码
* **Mocking 策略：** 使用 `mockall` 库进行依赖模拟
* **测试数据：** 使用 `test_data/` 目录存放测试用的 Fountain 文件

**前端测试：**
* **命名规范：** 测试文件命名为 `[组件名].test.tsx`
* **测试结构：** 使用 Jest + React Testing Library
* **Mocking 策略：** Mock Tauri API 调用和文件系统操作
* **测试数据：** 使用 `__mocks__/` 目录存放模拟数据

### **3.3 测试用例设计原则**

* **边界值测试：** 测试空文件、大文件、特殊字符等边界情况
* **错误处理测试：** 测试文件不存在、权限不足、格式错误等异常情况
* **用户场景测试：** 模拟真实用户的完整操作流程
* **性能基准测试：** 确保关键操作的性能指标符合要求

## **4\. 前端组件与 UX 设计规范**

### **4.1 通用组件库**

* **技术栈：** React 18 + TypeScript + Tailwind CSS
* **组件文档：** 使用 Storybook 进行组件文档化
* **无障碍性 (A11Y)：** 所有交互元素必须支持键盘导航和 ARIA 属性
* **响应式设计：** 支持不同屏幕尺寸，最小支持 1024x768 分辨率

### **4.2 核心组件规范**

**编辑器组件：**
* **功能：** WYSIWYG 剧本编辑，支持实时预览
* **API：** 提供 `onChange`、`onFocus`、`onBlur` 等事件回调
* **状态管理：** 使用 Zustand 管理编辑器状态
* **快捷键：** 支持常用编辑快捷键（Ctrl+S 保存、Ctrl+Z 撤销等）

**导航面板组件：**
* **功能：** 显示分幕结构和场景索引
* **交互：** 点击跳转到对应位置，支持折叠/展开
* **数据源：** 从编辑器内容实时解析生成

**工具栏组件：**
* **功能：** 提供格式切换按钮和编辑工具
* **布局：** 固定在编辑器顶部，响应式适配
* **状态：** 根据当前光标位置动态显示可用操作

### **4.3 状态管理规范**

**Store 结构：**
```typescript
interface AppState {
  // 编辑器状态
  editor: {
    content: string;
    cursorPosition: number;
    selectedElement: ElementType;
    isDirty: boolean;
  };
  
  // 文件状态
  file: {
    path: string | null;
    title: string;
    lastSaved: Date | null;
  };
  
  // UI 状态
  ui: {
    theme: 'light' | 'dark';
    fontSize: number;
    sidebarVisible: boolean;
    outlineVisible: boolean;
  };
  
  // 分幕结构
  structure: {
    acts: Act[];
    scenes: Scene[];
    characters: Character[];
  };
}
```

**数据操作：**
* 所有状态修改必须通过 Zustand 的 `set` 方法
* 复杂操作使用 Actions 封装
* 异步操作使用 `create` 方法创建独立的 store

### **4.4 主题和样式规范**

**设计系统：**
* **颜色方案：** 支持深色和浅色主题
* **字体：** 使用系统默认字体栈，支持字体大小调整
* **间距：** 使用 Tailwind 的间距系统（4px 基础单位）
* **动画：** 使用 CSS 过渡效果，持续时间不超过 300ms

**组件样式：**
* 使用 Tailwind CSS 类名
* 复杂样式使用 CSS Modules 或 Styled Components
* 响应式断点：`sm` (640px), `md` (768px), `lg` (1024px), `xl` (1280px)
